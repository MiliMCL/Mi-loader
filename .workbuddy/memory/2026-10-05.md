# 2026-10-05

## 修复 CI 反编译流水线从未真正执行 + 首次成功发布 v26.2

### 根因（三层，逐层暴露）
1. `test_client/` 在 .gitignore 中，Minecraft JAR 从未入库（仓库仅 400KB）。
   CI 的 `find . -path '*test_client*'` 永远找不到 → `found=false` →
   prepare/decompile/generate 全部 SKIPPED，且被 `onlyIf` 静默吞掉。
2. 由此 `minecraft.json` 从未被打进 JAR，`verifyPlatformJar` 报
   `META-INF/mili/minecraft.json missing`，release 在最后一步失败。
3. **关键坑**：`File(path).absoluteFile`（`resolveMinecraftArtifact` 与
   `minecraftArtifactSha256`）以 **Gradle daemon 的工作目录**
   （`~/.gradle/daemon/<ver>/`）为基准，而非项目目录。
   即使 JAR 已下载、`MINECRAFT_ARTIFACT=test_client/26.2.jar` 正确传入，
   仍解析成 `<daemon>/test_client/26.2.jar`（0 字节）→ 依旧 SKIP。
   这是"看起来都配对了却还是跳过"的真正原因。

### 改动（仅限构建报错与发布必要）
- ci.yml / release.yml：从 piston-meta 官方清单按 `minecraftVersion` 解析
  client 下载 URL，校验官方 SHA-1，导出**绝对路径** MINECRAFT_ARTIFACT。
  废弃原先探测仓库内 `test_client/` 的逻辑。
- mili-minecraft-integration：`resolveMinecraftArtifact` 相对路径锚定到
  projectDirectory；CFR `maxHeapSize = "4g"`（全量 MC 用默认堆会 OOM）。
- mili-loader：`minecraftArtifactSha256` 同样锚定项目目录；
  移除 skip-path 下失效的 `artifactSha256` 断言。

### 验证结果（v26.2 已发布）
- CI 三 job 全绿；真实反编译：10952 classes → 7055 sources →
  37 events / 10 registries（修复前全是 SKIPPED）。
- Release 产物 `mili-0.1.0-mc26.2.jar`（283,989 B，258 entries），
  SHA256SUMS 校验 OK，minecraft.json 指纹
  `40896ee9...290` 与官方 26.2 client.jar 完全一致。

### 重要结论：发布物是"加载器"，不含 Minecraft 本体
- JAR 内 `net/minecraft` 条目 = **0**，`org/loader` = 249，`.java` = 0。
- 这是 ADR 0005「Minecraft Is Host, Not Kernel」的设计刻意选择，
  也规避 Mojang 再分发条款；反编译源码仅作构建期元数据输入。
- 要真正"启动完整 Minecraft"，需 loader + 用户自备正版 MC 安装，
  由 `MinecraftDiscovery` 发现后以 URLClassLoader 同进程加载
  （入口 `net.minecraft.client.main.Main`）。
- 目前仓库无 distribution/application 插件，README 提到的 distTar/distZip
  与实际不符——如需开箱即用分发包需另行实现（本次未改，超出授权范围）。
