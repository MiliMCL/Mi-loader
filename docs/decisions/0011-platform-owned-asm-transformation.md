# ADR-0011: Platform-Owned ASM Transformation, Mods See Only Mili API

## Status
Accepted (2026-10-05)

Supersedes the blanket prohibition stated in `docs/history/ARCHITECTURE.md:358`
("禁止引入外部 Mixin、ASM、ByteBuddy、LaunchWrapper 等字节码改写框架，
所有 MC 桥接代码必须走纯反射").

That rule had already been broken in practice: `GeneratedBlockFactory`
declares `implementation("org.ow2.asm:asm:9.7.1")` and emits bytecode at runtime.
Rather than pretend the rule holds, this ADR replaces it with a rule that
matches what the platform actually needs and what it must still forbid.

## Context

Mili is built on the premise that mods interact with Minecraft through a
stable native ABI, with no Mixin in the dependency graph. Reflection alone,
however, cannot express three things mods genuinely need:

1. **Tick entry points.** `TickBridge.beginTick()` / `endTick()` are designed
   to be called from the real game tick loop, but nothing in the production
   path calls them. `TickBridge`'s own javadoc names the intended caller:
   "字节码注入或官方启动路径". Reflection cannot inject a call at the *start* of
   an existing method — it can only wrap it from outside, which cannot be done
   for a method the game calls directly on its own objects.
2. **Generated subclasses bound to game types.** A mod block must be a real
   `extends Block` instance for the game registry to accept it. Reflection
   cannot create an instance of a class that does not exist.
3. **Method/field interception.** Redirecting a call, injecting before a
   specific invocation, or modifying an argument requires bytecode rewriting.

Meanwhile the platform must keep Minecraft-specific knowledge out of the
Kernel (ADR-0009), keep the distribution free of Mojang content
(`distribution-boundary.gradle.kts`), and keep Mixin out of the infrastructure
forever.

## Decision

Mili implements a **platform-owned** bytecode transformation engine, built on
ASM, hidden behind a native Mili API.

**Allowed**

| Area | Rule |
|---|---|
| Bytecode library | ASM, inside platform modules only |
| Injection point | `MinecraftClassLoader` load path, **before** `defineClass` |
| Class generation | Runtime synthesis (already present via `GeneratedBlockFactory`) |
| Mod API surface | Annotations + callback interfaces from `mili-abi` only |
| Generated bytecode referencing mods | **Forbidden** — see below |
| Verification | `CheckClassAdapter` + `Analyzer` before every `defineClass` |

**Forbidden**

| Area | Rule |
|---|---|
| Mod-facing ASM | `ClassVisitor` / `MethodVisitor` / `InsnList` must never appear in a mod's compile classpath |
| Loader internals | `org.ow2.asm.**` in `mili-abi`; ASM never re-exported through ABI |
| Instrumentation | No `java.lang.instrument`, no `-javaagent`. Transformation happens at load time, not via retransformation |
| Mixin | Never a build, runtime, or compatibility dependency of any platform module |
| Mod privilege | Arbitrary class transformation requires the `TRANSFORM_*` capabilities; a plain mod transforms nothing by default |
| Overwrite | Disabled by default; requires `OVERWRITE_METHOD` capability **and** may never target a `phase = CORE` transformer |

**The generated-bytecode rule.** Injected bytecode must reference only
platform-owned dispatchers (`org.loader.loader.transform.dispatch.*`), never a
mod's classes or methods:

```
INVOKESTATIC org/loader/loader/transform/dispatch/TickCallbackDispatch.onTickEnter()V
```

This is what lets `ModClassLoader` be reclaimed independently, and it is why
`ClassVisibility` needs no new entries — the generated reference points at
`org.loader.*`, which is already `PARENT_FIRST` through `MinecraftClassLoader`.

## Consequences

**Accepted costs**

- ASM version becomes coupled to `javaVersion`. Minecraft 26.2 is class major
  69 (Java 25); ASM 9.7 throws `Unsupported class file major version 69`.
  The version is now a single source of truth in `gradle.properties` with the
  reason recorded inline, so raising `javaVersion` forces a deliberate review.
- Transformation bugs surface as `VerifyError` / `ClassFormatError` at class
  load. Mandatory verification (§23 of the engine design) exists to make these
  attributable rather than mysterious.
- Bytecode bugs can corrupt game state in ways reflection bugs cannot.
  Audit logging is therefore not optional.

**Gains**

- The tick chain finally closes: `MinecraftServer.tickServer` → `MiliTickTransformer`
  → `TickBridge` → `TickContract` → `TickEngine`. This is the first design in
  the repo where that chain is reachable at all.
- Future `RegionScheduler` / `TickPool` / parallel tick can rely on a real
  per-tick execution envelope rather than polled guesses.
- Mods get a capability comparable to Mixin's without Mixin's cost, and
  without mods ever touching ASM.

**Superseded, not forgotten**

The original rule's *intent* — keep the mod API native, keep Minecraft out of
the Kernel, forbid framework lock-in — is preserved in strengthened form. Only
the blanket ban on the tool is lifted. ADR-0009 (Minecraft as adapter) remains
in force: the engine treats bytecode as opaque `byte[]` plus strings and
imports no `net.minecraft.*` type.
